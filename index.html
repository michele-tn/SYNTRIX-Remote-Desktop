THE DIFFERENCE / OFFICIAL VS CUSTOM

Same foundation.
Specific changes.

This comparison describes the reviewed 1.5.3 baseline and the delivered SYNTRIX build. It does not claim a new protocol, stronger cryptography or blanket compatibility with every future upstream release.

Reviewed baseline: official tag 1.5.3 · SYNTRIX Windows x64 tray-only build, 19 November 2026
AreaOfficial RustDesk 1.5.3SYNTRIX custom edition
IdentityOfficial RustDesk product, icons and Windows resources.SYNTRIX Remote branding, Windows icons, product resources and upstream attribution.
Hide CM settingOn the reviewed 1.5.3 baseline, the desktop control is commented out; IPC visibility is gated by Pro/custom-client checks.The control is restored for the public build. IPC exposes the password-security hide_cm result without that Pro/custom gate.
Incoming sessionsThe upstream Connection Manager follows its normal startup and session-driven window behavior.With hide_cm active, authorized connections do not automatically show or focus the manager. Tray intent is tracked separately.
Tray and disconnectionStandard upstream tray behavior and connection controls.A local tray click requests the full Connection Manager for active sessions. The user can inspect permissions and disconnect there.
Compact session bannerNo claim is made that stock 1.5.3 contains the earlier SYNTRIX compact overlay.The compact “Remote session active / Disconnect” indicator introduced during SYNTRIX development has been removed.
Approval and passwordsUpstream authorization and password-security checks.Existing authorization requirements remain. Pending approval must still be delivered; hiding is not permission to bypass approval.
Windows integrationUpstream Windows class and standard portable extraction location.Dedicated SYNTRIX window discovery class and portable extraction directory. This is not complete configuration, service or IPC isolation.
Build deliveryOfficial upstream build and release workflow.Public/private packages, verified EXE + ZIP, SHA3-256 checksums and build reports. Public native diagnostic paths are normalized.
Automatic rebuildUpstream sources and CI tool versions are the inputs.New Python/PowerShell pipeline: resolve the newest release, prepare sources, apply a variant patch, provision tools, test, build and verify. No application installation.
Authorization still applies.

The hide_cm path is tied to the configured password and approval policy. A pending click-approval request must remain accessible. The tray-only behavior described here concerns eligible authorized sessions, not silent approval of unknown users.

WHAT WAS DONE / EVIDENCE

Built. Checked.
Published.

The final visibility fix removed the compact indicator and separated tray requests from session events. Both repositories were cleaned and published with the final packages and updated build tools.

Application checks

Three visibility regression tests passed. The public EXE contains 91 verified payload files; EXE/ZIP content and checksums were checked. Full manual remote-session testing is not recorded.

Updater checks

Nine Python tests and PowerShell syntax checks passed. Both variant patches applied to the current nightly source. The complete fresh-machine tool bootstrap and build pipeline has not yet been tested end to end.

Repository cleanup

10,511 generated or obsolete local files were removed, freeing about 7.08 GB. Current source, Git history and final packages were retained; historical references were archived privately.

Build-only automation.

The updater produces EXEs and packages. It does not replace an installed RustDesk application or restart its service or tray. Compiler setup can require Windows administrator privileges or a restart.
