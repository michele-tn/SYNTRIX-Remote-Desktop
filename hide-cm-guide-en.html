01 / START HERE

One download.
All the moving parts.

Use 64-bit Windows 10/11 with Internet access and enough disk space for sources, SDKs and native compilation. Start in a writable folder. The PowerShell entry point downloads an isolated Python runtime if a suitable Python is missing.

Download the ZIP, not just the two entry points.

The Python and PowerShell files rely on the build helpers, public customization profile, patch and baseline bridge archive. The complete ZIP below keeps them together. This public toolkit produces the public variant; private branding is not distributed here.

PowerShell · download, verify, inspect, build
$base = "https://github.com/michele-tn/RustDesk-hide_cm-revert/releases/latest/download"
$zip = Join-Path $PWD "SYNTRIX-Auto-Update-Fix.zip"
Invoke-WebRequest "$base/SYNTRIX-Auto-Update-Fix.zip" -OutFile $zip
Invoke-WebRequest "$base/SYNTRIX-Auto-Update-Fix.zip.sha256" -OutFile "$zip.sha256"
$expected = ((Get-Content -LiteralPath "$zip.sha256" -Raw).Trim() -split '\s+')[0]
if ((Get-FileHash -LiteralPath $zip -Algorithm SHA256).Hash -ne $expected) {
    throw "Toolkit checksum mismatch"
}
$destination = Join-Path $PWD ("SYNTRIX-Toolkit-" + (Get-Date -Format "yyyyMMdd-HHmmss"))
Expand-Archive -LiteralPath $zip -DestinationPath $destination
Set-Location -LiteralPath $destination
# Inspect the selected release before starting the build:
.\Update-Syntrix.ps1 -Plan
# Then generate the public EXE and ZIP (no app installation):
.\Update-Syntrix.ps1

The checksum detects a damaged or mismatched download; it is served from the same GitHub release and is not an independent signature. Read the scripts before running them. If the terminal blocks a downloaded script, use a process-scoped policy after review:

PowerShell · current terminal only
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\Update-Syntrix.ps1 -Plan
.\Update-Syntrix.ps1

Already have Python 3.11 or later? Use the equivalent Python entry point. Windows PowerShell/PowerShell is still required by the build helpers.

Python · equivalent entry point
python update_syntrix.py --plan
python update_syntrix.py

03 / UPSTREAM SELECTION

The newest release.
Not a fixed nightly.

The default auto channel compares published upstream releases, including prereleases. For the rolling nightly, it uses the Windows x64 asset update time rather than an unrelated Android upload or the original release creation date. A newer stable release wins over an older nightly.

Nightly source selection maps that Windows asset to a successful x64 workflow job and its exact commit. The old nightly Git tag can be stale; the script refuses to guess the source from that tag or a moving master branch. The verified selection on 19 November 2026 was 669cb8ac62aa20d3626395877d7dd0357aec7ed2, from run 44427384641. A later run can select a different release.

PowerShell · choose a mode
.\Update-Syntrix.ps1 -Plan
.\Update-Syntrix.ps1 -Channel stable
.\Update-Syntrix.ps1 -Channel nightly
.\Update-Syntrix.ps1 -Tag 1.5.3
.\Update-Syntrix.ps1 -PrepareOnly
.\Update-Syntrix.ps1 -Output C:\SYNTRIX-Builds

-Tag selects an explicitly published release tag. -PrepareOnly downloads sources, applies the patch and checks visibility invariants without compiling. -Force rebuilds even if a verified result already exists. Python uses --channel, --tag, --prepare-only, --output and --force.

05 / AUTOMATED BUILD

From source
to checked packages.

  1. Prepare an isolated checkout. Resolve the release and exact source commit, retrieve the baseline needed by the three-way patch, initialize submodules and verify the patch hash.
  2. Apply the customization. Check the tray-only visibility invariants. A patch conflict stops the process instead of silently dropping your changes.
  3. Restore native bridge files. Use the verified baseline archive for the baseline commit, or the matching official CI bridge artifact with its GitHub SHA-256 digest. The pipeline does not run the bridge code generator.
  4. Provision required tools. Git, Rust, Flutter, Visual Studio Build Tools with C++/Windows SDK, vcpkg/native ports, libclang and Python packaging dependencies. Versions are read from the selected upstream workflow where applicable. Downloads use official hashes or Authenticode verification.
  5. Compile and verify. Run the visibility regression tests, compile the native and Flutter components, pack the portable EXE, verify its embedded files, create the ZIP and generate checksums and reports.

Visual Studio setup can require administrator privileges. If a restart is required, the script stops; restart Windows and run it again. This is compiler setup, not RustDesk installation. Future upstream tool or workflow changes can require script maintenance.

Default locations
%LOCALAPPDATA%\SyntrixUpdater\work       # isolated source checkouts
%LOCALAPPDATA%\SyntrixUpdater\logs       # diagnostics and failure reports
%LOCALAPPDATA%\SyntrixUpdater\releases   # EXE, ZIP, checksums, reports
%USERPROFILE%\.syntrix-toolchain          # SDKs and build tools

Outputs are separated by customization variant, source commit and patch identity. The public toolkit contains one public profile. The complete SYNTRIX workspace also supports a private profile; those private patch files are not included in this public download.

No application deployment.

The scripts do not replace files in Program Files and do not restart an installed service or tray. Installing a generated package is a separate operation.

07 / RECOVERY

If the build stops.

A patch conflicts with the latest upstream

Read the failure report and checkout in the cache. Compare upstream changes with the patch and port the affected behavior deliberately. Do not ignore failed hunks or claim every future release is automatically compatible. Keep the last verified executable.

The bridge artifact is missing, expired or has no digest

The process stops rather than running an unsupported generator or using bindings from a different commit. Use the baseline release or a source revision whose verified matching artifact is available, or update the bridge distribution after review.

GitHub returns an API rate-limit error

Wait for the limit to reset or supply GITHUB_TOKEN / GH_TOKEN in the terminal environment. Do not put credentials in HTML, screenshots, command examples or committed files.

Windows requires elevation or a restart for build tools

Complete the compiler setup using normal Windows authorization. Restart if requested, then rerun the same updater. The updater never treats elapsed time as approval and does not silently restart Windows.

The manager or small banner still appears

First confirm you launched the generated SYNTRIX package, not an older installed RustDesk process. Verify the hide setting, password/approval eligibility and actual build report. The updater leaves installed application files and services unchanged. Retest tray opening and session events on the intended build.

I only downloaded update_syntrix.py and Update-Syntrix.ps1

Download and extract the complete toolkit. Both entry points need the accompanying helpers, public profile, patch and bridge archive. Downloading the two scripts alone is not a complete build environment.
